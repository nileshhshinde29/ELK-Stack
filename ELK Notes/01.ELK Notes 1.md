# ElK questions and ans

### What is elastic search and why it is better than other?

- Elasticsearch is a tool used to store, search, and analyze large amounts of data very quickly, especially logs.

### What Is Log Analysis?

- Process of analyzing computer generated data to extract analyze log, meaningful insights, patterns.

### Advantages of Elasticsearch?

- Highly used for store, search and analyze the data very quickly, especially logs.
- Elastic Common Schema (ECS): normalize un-consistent logs in standard formate.
- Pri-building integration: elastic agents automatically parses data into standard formate like Apache.
- Ingest pipeline: Native grok and Dissect processors are present to filter and structure out data.
- use date processor to ingest pipeline to parse multiple pattern and convert into UTC
- Data streams: ship all logs into unified streams for standardized storage and also can automatic rollover index.
- Cross-Cluster-Search( CCS ): Enable single plane of glass visibility across multiple region without moving data
- Can use kibana for visualize  dashboards.
- 300+ pre-build integrations for ready to build pipelines
- automatically manage data retention by using ILMs phases.

### What is cluster?

- It is group of one or more elastic nodes that work as a single system to store, search and process data.

### What is cluster health?

- Green: All primary and replica shards are allocated.
- Yellow: Primary shards are allocated, but some replicas are not.
- Red: One or more primary shards are unavailable.
- ``json GET /_cluster/health ``

### What would you do if Elasticsearch health is red?

I would first identify the unassigned shards.
``GET /_cluster/health``

Then:

``GET /_cat/shards?v``

and investigate unassigned shards using the allocation explanation API.

- I would check:
  - Node availability
  - Disk space
  - Shard allocation rules
  - Index corruption
  - Cluster/node logs
  - Resource availability
- I would avoid immediately deleting data because the root cause needs to be understood first.

### What is TLS and SSL?

- **TLS** stands for **Transport Layer Security**.
- **SSL** stands for **Secure Sockets Layer**.
- SSL is the older security protocol, while TLS is its newer and more secure replacement.
- In Elasticsearch, TLS is mainly used to **secure and encrypt communication** between Elasticsearch components and clients.
- TLS helps protect:

  - Username and password
  - Elasticsearch data
  - API requests and responses
  - Communication between Elasticsearch nodes

### What is Transport SSL?

- Transport SSL is used specifically to **secure communication between Elasticsearch nodes**.
- Elasticsearch nodes use TLS/SSL to encrypt their communication with each other.
- It helps provide:

  - Encryption
  - Authentication
  - Data integrity
- Example:
  Node 1 → **TLS/SSL** → Node 2

# Kibana – Interview Notes

### Q1. What is Kibana?

Kibana is a **web-based tool used with Elasticsearch**. It helps us **search, analyze, visualize, and monitor data** stored in Elasticsearch.

We can do most of the analysis from the **browser UI**, so we don't always need to use the command line.

---

### Q2. Why do we use Kibana?

We use Kibana because:

* It provides an easy UI to search logs and data.
* We can create **real-time dashboards**.
* We can create different charts using **Lens**.
* We can monitor logs, metrics, and application data from one place.
* It is commonly used for **DevOps, Security, and Application Monitoring**.---

# Core Features

### Q5. What are the main things we can do in Kibana?

Some important features of Kibana are:

* **Discover** – Search, filter, and analyze Elasticsearch data.
* **Visualize / Lens** – Create charts and visualizations.
* **Dashboard** – Combine multiple visualizations in one place.
* **TSVB** – Used mainly for time-series data like rate, latency, and trends.
* **Machine Learning** – Can detect unusual patterns or anomalies.
* **APM** – Used for application performance monitoring.
* **SIEM / Security** – Used for security monitoring and threat detection.
* **Stack Monitoring** – Used to monitor Elasticsearch, Kibana, and other Elastic components.
* **Alerts** – Used to generate alerts based on specific conditions.

---

### Q6. What is Discover and why is it used?

**Discover** is used to search and explore the data stored in Elasticsearch.

We can select a **time range**, apply filters, and search for specific logs or events.

For example, if I want to find all **ERROR logs from the last 15 minutes**, I can do that from Discover.

It is mainly useful for **troubleshooting and finding the root cause of an issue**.

---

### Q7. What is Visualize?

Visualize is used to **represent Elasticsearch data in graphical form**.

### Q8. What is a Dashboard?

A Dashboard is a **single screen where we can combine multiple visualizations, charts, and filters**.

### Q9. When should we use TSVB?

TSVB stands for **Time Series Visual Builder**.

We mainly use it when we want to analyze data **over time**.

For example:

* Requests per second
* Response time
* Error rate
* Website traffic
* CPU usage

It is useful when we want to identify **trends, spikes, or sudden changes over time**.

---

### Q10. What does the Machine Learning feature do?

Machine Learning can help us **find unusual patterns in the data automatically**.

Instead of creating every rule manually, ML can identify abnormal behavior.

For example, if normally there are 10 login attempts but suddenly there are hundreds of login attempts, ML can identify this as an unusual pattern.

It can be useful for **early detection of problems or security-related activity**.

# Kibana Configuration – `kibana.yml`

### Q12. Which file is used to configure Kibana?

The main configuration file is:

`kibana.yml`

Some important configuration areas are:

* Server configuration
* Elasticsearch connection
* Authentication
* SSL/TLS configuration

---

### Q13. What do the server settings do?

Two important settings are:

```yaml
server.port: 5601
server.host: "localhost"
```

`server.port: 5601` means Kibana will run on **port 5601**.

`server.host: "localhost"` means Kibana will listen only on the local machine.

If we want users from other machines to access Kibana directly, we need to configure the host appropriately.

---

### Q14. How does Kibana know which Elasticsearch server to connect to?

We configure Elasticsearch in `kibana.yml` using:

```yaml
elasticsearch.hosts: ["https://localhost:9200"]
```

Here:

* `localhost` = Elasticsearch is running on the same machine.
* `9200` = Elasticsearch default port.
* `https` = Connection is using TLS/SSL.

So basically, this tells Kibana **where Elasticsearch is running and how to connect to it**.

---

### Q15. Which user does Kibana use to connect to Elasticsearch?

Kibana normally uses the built-in:

**`kibana_system` user**

The credentials are configured using:

```yaml
elasticsearch.username
elasticsearch.password
```

The `kibana_system` user is mainly used for **Kibana's internal/background operations**, such as managing Kibana-related indices and other internal tasks.

---

### Q16. What is the best way to store the Kibana password?

We should **not store sensitive passwords directly in `kibana.yml`**, especially in production.

Instead, we should use the **Kibana keystore** to securely store sensitive values.

For example:

```bash
bin/kibana-keystore add elasticsearch.password
```

This is safer than keeping the password directly in the configuration file.

---

### Q17. Explain the three SSL/TLS settings.

There are three important settings:

| Setting                                      | What it does                                              | Simple example      |
| -------------------------------------------- | --------------------------------------------------------- | ------------------- |
| `elasticsearch.ssl.certificate`            | Certificate used to identify Kibana to Elasticsearch      | Kibana's ID card    |
| `elasticsearch.ssl.key`                    | Private key associated with the certificate               | Kibana's secret key |
| `elasticsearch.ssl.certificateAuthorities` | CA certificate used to verify Elasticsearch's certificate | Trusted authority   |

In simple words:

* **Certificate** → tells Elasticsearch who Kibana is.
* **Private key** → proves that Kibana owns that certificate.
* **CA certificate** → tells Kibana which certificates it should trust.

The private key should always be kept secure and should not be shared.

---

### Q18. Explain the secure connection flow.

The basic flow is:

**User → Kibana → Elasticsearch**

1. The user opens Kibana in the browser, usually on **port 5601**.
2. Kibana connects to Elasticsearch, usually on **port 9200**.
3. If HTTPS/TLS is configured, the communication between Kibana and Elasticsearch is encrypted.
4. Certificates are used to establish trust between the systems.
5. Kibana authenticates with Elasticsearch using its configured credentials.
6. Elasticsearch processes the request and sends the data back to Kibana.
7. Kibana displays the data in the browser.

So TLS helps **secure the communication**, while `kibana_system` is used for Kibana's internal communication and operations.
