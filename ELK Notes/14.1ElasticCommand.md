- PUT _cluster/settings
 {
  "persistent": {
    "cluster.routing.allocation.disk.watermark.low": "85%",
    "cluster.routing.allocation.disk.watermark.high": "90%",
    "cluster.routing.allocation.disk.watermark.flood_stage": "95%"
  }
}


- Watermark is act like a threshold.
- if we have 2 node and one node is reaches to flood stage then ES can start data into node 2.
but it depends on Allocation rules, data size etc.
- low: Try to avoid allocating new shards to that node. try to relocate shards to free nodes
- High:  more strict about disk space. Generally not allocate new shard to that node. try to move shard to another node.
- can apply read_only_allow_delete block at this node.

### VIMP: 
- When we have added mapping and then after some time we need to change data type of particular field.
- Then we change the index template. but even inserting new documents in this index still that document will have previous data type. It will applicable only after the rollover the index. But we cant wait for rollover automatically by Ilm policy
- but if we you add flipkart/_rollover then new index is created but sometimes it give conflict for datatype.
- so we can you reindex as shown as bellow. it copy all doc and create new index. also new document can be inserted with new data type immediately.


Post logs-flipkart-prod/_create/1
{
    "user_name":"nilesh shinde",
    "user_ip":"192.168.1.10",
    "status_code":"200"
}

POST _reindex
{
  "source": {
    "index": ".ds-logs-amezon-prod-2026.10.19-000001"
  },
  "dest": {
    "index": "ds-logs-amezon-prod-000001"
  }
}
