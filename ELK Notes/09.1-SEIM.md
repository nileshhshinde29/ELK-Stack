SIEM stands for Security Information and Event Management.

- its is collect security logs from multiple sources, analyze them detect suspicious activities. if any then generate an alert.
- common data sources: servers and applications, linux /windows sys. firewall and network devices, VPN

Main Elastic Security Features
- detect suspicious activities by given condition
- notify team using alert when activities is there
- It used time line to investigate and correlate events
- cases used to tract, and manage security incidents
- Elastic agent iterations used to get data form different sources

What is a Detection Rule?
- it is check incoming logs against predefined conditions.
- types as below

1. Custom Query Rule
- it uses KQL or lucence to find matching condition.
- example: xyz.event.action :"authentication_failed" 

2. Threshold Rule
- It is used to generate alert when certain no of events occurs within specific time.
- eg alert when users authentication failed 5 times when 10 users match this condition send an alert.

xyz.event.action: "authentication_failed"  
    group by host.ip >=5
    count: user.name >=10 unique values

Collects => security logs from servers, endpoints, application.

Ingest => Elastic Agents, beats or other integrations to collect the data 

in security tab => Rules => create

used for events like deleting, authentication failed and more issues like this.

for delete object detection

3. EQL Rule
- it uses EQL to find and match condition for alert

4. Indicator match rule.
- in this rule we store suspicious users, ip, or field which is given by thread intelligence and check them with our system events logs

- query: source.ip : * or destination.ip : * 
 field => client.ip  
 indicator index field => threat.indicator.ip

 field <=> matches indicator <=> index fields

5. Machine Learning Rule
It create alert when ML detect abnormal behavior.  
eg. 1
 ML Job: high_outbound_traffic
 Anomaly threshold: 50

6. New Terms Rule
It create alert when new value is appeared in logs 
- eg
Index: user-logs-*
Field: user.name 
History window: 7 days

if new user is there then alert generated

7. Event co-relation rule.
 it is used when you have to add rule for sequences.

 sequence by user.name with maxspan=10m
  [ any where event.category == "authentication" and event.outcome == "failure" ] with runs = 5
  [ any where event.category == "authentication" and event.outcome == "success" ]
  [ any where event.action == "password_change" ]
  [ any where event.action == "file_download" and file.size >= 100000000 ]

#### IMP: Additional look back time = 2 min means if interval ia 5 min then also it checks previous 7 min. useful when logs coming late

## What is MITRE ATT&CK?

MITRE ATT&CK is a knowledge base of attacker tactics and techniques. It helps security teams understand attacker behavior and map their detection rules to known attack techniques.

tactic= why
tequenique = how

#### Important MITRE ATT&CK Tactics
Tactic	Meaning	Example
Initial Access	Gain entry	Phishing
Execution	Run code	PowerShell
Persistence	Maintain access	Create Account
Privilege Escalation	Gain higher privileges	Exploitation for Privilege Escalation
Defense Evasion	Avoid detection	Disable security tools
Credential Access	Steal credentials	Brute Force

### Q12. What is the difference between a tactic and a technique?

A tactic explains why an attacker performs an action,
while a technique explains how the attacker performs it.

## Timeline vs Cases – Example
- Timeline helps us investigate what happened before, during, and after the alert.
- After confirming that the activity is suspicious, the analyst creates a Case. Cases help us document, manage, and track the security incident.

eg
Suppose a user's account is compromised and an alert is generated because there were multiple failed logins followed by a successful login.

Timeline

The analyst opens Timeline and investigates:

10:00 AM → 5 failed login attempts
10:02 AM → Successful login from a new IP
10:05 AM → Password changed
10:10 AM → Large amount of data downloaded

Cases
The Case can contain:

Alert details
Timeline investigation
Evidence and screenshots
Analyst comments
Investigation status
Actions taken, such as blocking the user
