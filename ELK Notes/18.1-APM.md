## 1. APM Basics

### What is APM?
- **Application Performance Monitoring**
- Monitors application **performance, response time, errors and slow APIs**.
- **Example:** Amazon's product page is loading slowly → APM shows which part is slow.

## 2. Core Concepts

### What is the hierarchy of Trace, Transaction and Span, and their IDs?

```
TRACE            ← complete request journey      (top)
└── TRANSACTION  ← one operation per service
    └── SPAN     ← small step inside a transaction (bottom)
        └── SPAN ← child span
```

| Level | Concept | Meaning | Contains | ID | Amazon Example |
|-------|---------|---------|----------|----|----------------|
| 1 | **Trace** | Complete journey of a request from start to finish | One or more **transactions** | **Trace ID** – **shared by everything** in the trace; connects all operations of one request | Place Order: checkout → payment confirmation. Trace ID finds all operations of one order |
| 2 | **Transaction** | One complete operation monitored in a service | Multiple **spans** | **Transaction ID** – unique for each transaction | `Create order` in Order Service |
| 3 | **Span** | One small operation **inside** a transaction | Child **spans** (parent-child) | **Span ID** – **unique for each span**; identifies one exact operation | Check stock, calculate price, call bank API. Span ID finds the exact payment API call that failed |

---

### What is Distributed Tracing?
- Tracks **one request across multiple services**.
- Helps identify **which service is slow or failing**.
- All related spans keep the **same Trace ID, even across services**.
- Separate operations (e.g. Login and Add to Cart) get **different Trace IDs**; operations that are part of **one distributed request** share the **same Trace ID**.

## 3. One Example – Everything Together

```
User clicks "Place Order" on Amazon
│
▼
TRACE ─── Trace ID: 1234  (same ID travels across every service = Distributed Tracing)
│
├── Checkout Service ── TRANSACTION: POST /checkout
│   ├── SPAN 11: Validate cart                    20 ms
│   └── SPAN 12: Call Order Service ──────────────┐
│                                                 ▼
├── Order Service ───── TRANSACTION: Create order
│   ├── SPAN 21: Check stock                      30 ms
│   ├── SPAN 22: Calculate price                  15 ms
│   └── SPAN 23: Call Payment Service ────────────┐
│                                                 ▼
└── Payment Service ─── TRANSACTION: Process payment
    └── SPAN 31: Charge card          ← parent span
        └── SPAN 32: Call bank API    ← child span   2500 ms ⚠ SLOW
```

| What you see | Concept |
|--------------|---------|
| Whole tree, from click to bank API | **Trace** (level 1) |
| `POST /checkout`, `Create order`, `Process payment` | **Transactions** (level 2, one per service) |
| `SPAN 11`, `SPAN 21`, `SPAN 32` … | **Spans** (level 3), each with a unique **Span ID** |
| SPAN 31 → SPAN 32 | **Parent-child** spans |
| `1234` at the top | **Trace ID** (shared by everything below it) |
| Checkout → Order → Payment | **Distributed tracing** |
| SPAN 32 = 2500 ms | **APM** finds the bottleneck → the bank API in Payment Service |

---

## 4. Quick Revision

| Concept | Key point |
|---------|-----------|
| **Trace** | Complete request journey (top level) |
| **Transaction** | One monitored operation per service, inside a trace |
| **Span** | One small operation inside a transaction |
| **Parent-child** | Spans can have child spans |
| **Trace ID** | Shared by all transactions and spans in the same trace |
| **Span ID** | Unique for each span |
| **Distributed tracing** | Follows one trace across multiple services |


# APM Setup – Quick Notes

```
[App + Agent] --8200--> [APM Server] --> [Elasticsearch] --> [Kibana]
                             ^
                     [Fleet Server :8220]
```

## Ask first
- Which technology + version?
- Where is the config file?
- Which is the root file (runs first)?

## Steps
1. Kibana → Fleet → add APM Server (install it if missing)
2. Application → APM → select technology (e.g. Node.js)
3. Install agent: `npm install elastic-apm-node`
4. Add APM server URL + secret token at the **top of the root file**
5. Restart the app
6. Check Kibana → APM → Services

## Node.js snippet
```js
require('elastic-apm-node').start({
  serviceName: 'my-app',
  serverUrl: 'http://<ip>:8200',
  secretToken: '<token>'
});
```

## Restart commands
```bash
pm2 restart <app-name>          # PM2
npm start                       # plain npm
sudo systemctl restart <service> # systemd service
docker restart <container>      # Docker
```
APM Server / Fleet (if self-installed):
```bash
sudo systemctl restart apm-server
sudo systemctl restart elastic-agent
```

## Ports
- Fleet: **8220**
- APM: **8200**
