## 1. Basics

### Where do we find CCS and CCR in Kibana?
- Go to **Stack Management**. There are two options:
  1. **Remote Clusters** – used for CCS (and needed for CCR)
  2. **Cross-Cluster Replication** – used for CCR

---

## 2. Remote Cluster (CCS)

### How to add a remote cluster?
1. Stack Management → **Remote Clusters** → **Add a remote cluster**
2. Give a **remote cluster name** (e.g. `DR`)
3. Add the **host and port** of the remote cluster
   - Only **master / master-eligible node IPs** are required
   - Use port **9300** – default port for internal node-to-node communication

### How to check which remote clusters are connected?
```
GET _remote/info
```
- Shows which clusters are connected as remote.
- Same info is also visible in the Kibana UI.

### How to search an index from a remote cluster?
- Format: `<remote_cluster_name>:<index_name>`
```
GET DR:student/_search
```

### Use case
- We can keep **one Kibana only for searching**, and connect all other clusters to it as remote clusters.

## 3. Cross Cluster Replication (CCR)

### What is CCR?
- Whatever data is inserted in the **leader index** is automatically copied to the **follower index**.
- Used for **high availability** of data (e.g. DR setup).

| Term | Meaning |
|------|---------|
| **Leader index** | Index where data is ingested |
| **Follower index** | Index where data is copied |

### How to set up CCR?
1. Connect both clusters to each other as **remote clusters** (do setup on **both** clusters).
2. Stack Management → **Cross-Cluster Replication** → Create.
3. Add the **leader index** and **follower index** as per requirement.

- Setup is needed **for each index separately**.

### IMP
- If cluster 1 (leader) is **down**, new data will **not** be copied to cluster 2.
- But the **previous (already copied) data is still available** in the follower index.

---

## 4. Quick Revision

| Concept | Key point |
|---------|-----------|
| **CCS** | Search data of another cluster from one cluster |
| **CCR** | Copy data from leader index to follower index |
| **Remote cluster port** | 9300 (internal communication) |
| **Remote cluster nodes** | Only master / master-eligible node IPs |
| **Check remote clusters** | `GET _remote/info` |
| **Remote search** | `GET DR:student/_search` |
| **CCR setup** | Per index, both clusters connected as remote |
| **Leader down** | No new data copied; old data still available |
